# PHASE 25 — Eval integrity: honest labeling + de-circularize expert gold

**Priority:** P0 (credibility risk — fix first)
**Effort:** 1 day
**PS rows touched:** R2, R3, R9, R16, R17 (evidence integrity behind "verified outcome data")
**Non-negotiable this phase enforces:** RULES.md §3 — "no fabricated data presented as real."

## Why this phase exists

An independent read of `eval/scripts/build_expert_gold.py` and `scripts/build_plfs_aggregates.py`
found that `docs/EVAL_REPORT.md`'s "Tier 2 — Expert- and Pilot-Validated Metrics" table is not
what its name claims:

- The "3 independent vocational counsellors" are not people. `build_expert_gold.py` computes a
  `latent` suitability score from `0.55*cosine_similarity + 0.30*overlap + 0.15*mean(aptitude)`
  — the *same* features the recommender itself scores with — then adds `np.random.default_rng`
  noise to simulate "rater disagreement." The reported Krippendorff's alpha is close to
  guaranteed by this construction, and grading the model against labels derived from the
  model's own signal is circular.
- The "PLFS 2023–24 Unit Microdata, n=12,525" does not exist in this repo.
  `build_plfs_aggregates.py`'s `generate_seed_plfs_microdata_if_missing()` silently writes
  50,000 synthetic rows with `rng.gauss()` around hardcoded base salaries whenever the real raw
  file is absent — which it currently is.
- Only Tier 3 of `EVAL_REPORT.md` is labeled "SIMULATED." Tier 2, which has the most
  impressive-looking statistics (confidence intervals, alpha, n= counts), is not — even though
  it is equally synthetic.

Any judge who opens `eval/scripts/` will find this in minutes. Fix the labeling and the
circularity before that happens.

## Prompt

PHASE 25 — EVAL INTEGRITY.

1. In `docs/EVAL_REPORT.md`, rename "Tier 2 — Expert- and Pilot-Validated Metrics" to
   "Tier 2 — Algorithmically-Simulated Validation (structurally realistic, not yet
   real-world)" unless real pilot data exists (see step 5). Add a visible notice box at the
   top of that section stating plainly that the counsellor ratings and the PLFS microdata are
   generated by `eval/scripts/build_expert_gold.py` and the fallback generator in
   `scripts/build_plfs_aggregates.py` because no real counsellor panel or downloaded PLFS unit
   file exists yet, and that these numbers are internal regression tests, not external
   validation. Use the same visual/textual convention already used for `is_demo=true` badges
   elsewhere in the product.
2. Add a `Data` column to every row of the Tier 1 and Tier 2 tables in `EVAL_REPORT.md`
   tagging it `REAL` or `SYNTHETIC` based on its actual source. No row may say `REAL` unless a
   file in `data/raw/` (not auto-generated) backs it.
3. Fix the circularity in `eval/scripts/build_expert_gold.py`: the `latent` suitability formula
   must stop reusing the ranker's own cosine/overlap/aptitude features as its ground truth.
   Replace it with a hand-authored rubric keyed off persona attributes that the ranker does
   *not* directly see as a single feature — e.g. a lookup table in `eval/gold/rubric.md` mapping
   (household income tier × district trade-demand note × stated safety concern) to a suitability
   band, authored by you, not derived from `centered_cosine`/`_top3_letters`. Keep the simulated
   multi-rater noise step, but make the base label independent of the model's internal math.
   Document the independence explicitly in a new `eval/gold/METHODS.md`.
4. In `scripts/build_plfs_aggregates.py`, make `generate_seed_plfs_microdata_if_missing()` loud
   instead of silent: when the real raw file is absent it must print a clear `WARNING:
   generating SYNTHETIC fallback microdata — not real PLFS data` to stderr, and every row it
   writes to `plfs_earnings_aggregates.csv` / `education_route_compare.csv` must carry
   `source=synthetic_fallback_2026`, `is_demo=true`. Propagate that provenance into the
   `EVAL_REPORT.md` Tier 2 table via the new `Data` column from step 2.
5. Add `scripts/data_provenance_audit.py`: it scans `EVAL_REPORT.md` for any numeric claim in a
   table and fails if that table lacks a `Data` column or contains a `SYNTHETIC`-sourced number
   without the word "SIMULATED" or "SYNTHETIC" present in that table's own caption. Wire it into
   `make check`.
6. Stretch goal, only if time remains before submission: collect even 5–10 real ratings. Ask
   2–3 real people (ideally someone with ITI/vocational-training exposure) to blind-rate 10–15
   persona-course pairs. Save as `eval/gold/real_pilot_ratings.csv` (rater identity redacted),
   and add it to `EVAL_REPORT.md` as a small, honestly-labeled `n=X, real raters, exploratory`
   row placed *next to*, not blended into, the simulated numbers.
7. Update `docs/PS_TRACEABILITY.md` rows R2, R3, R9 evidence cells to point at
   `eval/gold/METHODS.md` and the new provenance audit.

## Gate (acceptance)

- `make check` passes, including the new `scripts/data_provenance_audit.py` step.
- Every number in `EVAL_REPORT.md` Tier 1/Tier 2 carries an explicit `REAL` or `SYNTHETIC` tag
  in a `Data` column, and every table containing a `SYNTHETIC` number says so in its caption.
- `eval/gold/build_expert_gold.py`'s base suitability label no longer reuses the ranker's own
  `centered_cosine`/`_top3_letters` features as its sole ground-truth signal — confirm by
  diffing the function against this phase's starting version.
- `eval/gold/METHODS.md` exists and states, in plain language, what is simulated and why.
