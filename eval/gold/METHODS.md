**Version:** 25.0 (2026-10-17)

## 1. What this document covers

This document describes the methodology used to generate `eval/gold/expert_ratings.csv` — the
ground-truth suitability labels used in Tier 2 of `docs/EVAL_REPORT.md` — and explicitly
documents why the base label is **independent** of the KaushalPath ranking model's internal math.

---

## 2. What changed in Phase 25 (the circularity fix)

### Phase 24 (old) — CIRCULAR

The old `build_expert_gold.py` computed a `latent` suitability score as:

```python
latent = 0.55 * centered_cosine(p_vec, o_vec)
       + 0.30 * overlap(_top3_letters(p_vec), _top3_letters(o_vec))
       + 0.15 * (mean(aptitude) / 10.0)
```

This was **circular** because:
- `centered_cosine` is the **primary ranking feature** in `app/ml/ranking/features.py`
- `_top3_letters` set-overlap is the **secondary ranking feature**
- `mean(aptitude)` is used in aptitude fit scoring

Grading the model against labels derived from the model's own signals guaranteed high NDCG@5
(≈ 0.91) by construction — not because the recommender was good.

### Phase 25 (current) — INDEPENDENT

The base suitability label is now computed by `_counsel_rubric()` in the new
`build_expert_gold.py`. It uses **five axes keyed off persona attributes that the
ranker does not see as a single combined signal**:

| Axis | Persona attribute used | Ranker's corresponding feature | Independent? |
|---|---|---|---|
| 1. District demand | `district` → cluster lookup table | No corresponding feature (ranker uses `local_demand` from Market DB rows, not persona district) | ✅ |
| 2. Econ fit | `budget_band`, course `fee_inr`, `duration_months` | `net_cost_ratio` (partially overlapping but not the rubric formula) | ✅ partial |
| 3. Env/safety | `relocate_ok` → cluster type lookup | `distance_km` (proximity, not physical environment compatibility) | ✅ |
| 4. Edu pathway | `edu_level`, course `min_edu`, course `nsqf_level` | `nsqf_level` used in `aptitude_fit_occ` but not as a standalone ground-truth axis | ✅ partial |
| 5. RIASEC archetype | Top letter of `riasec` dict (direct read) | `riasec_cosine` and `top3_overlap` (vector dot-product and set-intersection) | ✅ **No dot-product used** |

**Key independence guarantee:** Axis 5 reads only `max(riasec.keys(), key=riasec[k])` —
the single top Holland letter. It does NOT call `centered_cosine()` or `_top3_letters()`.
The composite is a lookup table (top-letter → cluster → score), not a vector operation.

## 3. What is SIMULATED and what is REAL

| Layer | Status | What it is |
|---|---|---|
| **Base rubric labels** | SIMULATED (algorithm-authored) | A hand-written counsellor rubric coded by the dev team, not ratings from real humans |
| **Multi-rater noise** | SIMULATED | 3 synthetic "raters" drawn from a noise model (85% agreement, 8% −1, 7% +1) |
| **Krippendorff's alpha** | SIMULATED consequence | Alpha reflects the noise model's construction, not real inter-rater agreement |
| **NDCG@5 / Hit-rate** | VALID INTERNAL CHECK | Measures whether the ranker's ordering matches the rubric's ordering — not circular since rubric ≠ ranker formula |
| **PLFS microdata** | SYNTHETIC FALLBACK | Generated by `scripts/build_plfs_aggregates.py::generate_seed_plfs_microdata_if_missing()` since real PLFS unit file is absent. Every row carries `source=synthetic_fallback_2026, is_demo=true` |

## 5. Inter-rater reliability

With the new rubric, Krippendorff's α ≈ 0.73–0.79 across 160 personas (target ≥ 0.60).

The alpha is lower than the old circular value (≈ 0.79 with the old formula) because the rubric
introduces genuine variation: some personas score 2 on most axes but 1 on district demand, giving
a realistic mix of borderline labels where rater noise produces disagreement.

---

## 6. What Phase 25 still does NOT do (honest gaps)

- **No real human raters.** The "counsellors" are simulated. Stretch goal (Phase 25, Step 6)
  is to collect 5–10 real ratings from people with ITI/vocational exposure and add them as an
  `n=X, real raters, exploratory` row in `EVAL_REPORT.md`.
- **PLFS microdata is synthetic.** The real PLFS 2023–24 unit-level file is not committed to
  this repository (it is a large government dataset). The synthetic fallback is clearly labeled
  `source=synthetic_fallback_2026` and `is_demo=true` in every row.
